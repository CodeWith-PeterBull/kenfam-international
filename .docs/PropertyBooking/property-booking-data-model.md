# Property Booking Data Model And Migration Plan

**Status:** Implemented through Phase 2. Later-phase booking, POB, and operations behavior remains governed by this contract.

## 1. Persistence Rules

- All module tables use a `property_booking_` prefix except the aggregate table
  `property_bookings`, keeping database ownership visible and avoiding generic
  `properties`, `units`, `guests`, `payments`, or `registers` collisions.
- Integer auto-increment IDs remain primary keys and all foreign keys remain
  integers.
- Externally addressable aggregates receive a separate immutable `ulid` column
  generated by a module-owned `HasUlid` concern.
- Every migration column, including timestamps and actor columns, receives a
  specific `->comment()`.
- Money is an unsigned integer in configured currency minor units. Percentages
  and tax rates use basis points.
- Property-local date/time input is converted to UTC before persistence. The
  property's IANA timezone is snapshotted on each booking.
- Financial and booking snapshots survive catalog changes and soft deletion.
- Booking, assignment, charge, payment, and shift records are lifecycle-managed;
  they are not removed through ordinary CRUD.
- Foreign keys use `cascadeOnDelete()` only for true aggregate children/pivots.
  Historical links to catalog, guest, register, shift, or users use
  `nullOnDelete()` where deletion is otherwise permitted.
- Explicit short index names are mandatory to remain below database identifier
  limits despite the module table prefix.

## 4. Ordered Tables And Fields

### 4.1 `property_booking_categories`

Classifies establishments without confusing a property category with a unit
type.

Fields:

- `id`, `ulid`;
- nullable self-referencing `parent_id`;
- `name`, globally unique `slug`, nullable `description`;
- `sort_order`, `is_active`;
- `created_at`, `updated_at`.

Constraints/indexes:

- unique `ulid` and `slug`;
- navigation index on `parent_id`, `is_active`, `sort_order`.

Media collection:

- single `category_image` with accessible alt-text custom property.

### 4.2 `property_booking_properties`

Owns one accommodation establishment/address and its booking policy defaults.

Fields:

- identity/ownership: `id`, `ulid`, nullable `category_id`, unique `code`,
  unique `slug`, `name`, `status`;
- actors: nullable `created_by`, `updated_by`;
- content: nullable `short_description`, `description`, `house_rules`,
  `cancellation_summary`;
- contact: nullable `email`, `phone`, `whatsapp_phone`, `website_url`;
- address: nullable `address_line_1`, `address_line_2`, `city`, `region`,
  `postal_code`; required ISO `country_code`;
- geolocation: nullable signed decimal `latitude`, `longitude`;
- operating context: IANA `timezone`, ISO currency `currency`;
- policy windows: nullable `check_in_from`, `check_in_until`, `check_out_from`,
  `check_out_until`; `minimum_notice_minutes`, nullable
  `maximum_advance_days`; unsigned `turnover_minutes`;
- merchandising: `is_featured`, nullable `meta_title`, `meta_description`,
  `published_at`;
- `created_at`, `updated_at`, `deleted_at`.

Constraints/indexes:

- publication index on `status`, `published_at`;
- discovery indexes on `category_id`, `status`, and `is_featured`, `status`;
- location index on `country_code`, `region`, `city`;
- latitude range `-90..90`, longitude range `-180..180`, and IANA timezone are
  enforced by forms/services because portable database checks differ.

Media collections:

- single `property_cover`;
- ordered `property_gallery` with configured cap.

### 4.3 `property_booking_property_user`

Scopes non-administrator operators to properties.

Fields:

- `property_id`, `user_id`;
- nullable `assigned_by`;
- `is_default`;
- `created_at`, `updated_at`.

Constraints:

- composite primary/unique key on `property_id`, `user_id`;
- index on `user_id`, `is_default`;
- property deletion cascades; user/assigner deletion removes or nulls only the
  appropriate link.

### 4.4 `property_booking_amenities`

Defines reusable, filterable facilities/features.

Fields:

- `id`, `ulid`, unique `name`, unique `slug`;
- `scope`, nullable `description`, nullable `icon_key`;
- `sort_order`, `is_active`;
- `created_at`, `updated_at`.

`icon_key` stores a validated icon-library key, never raw SVG/HTML.

### 4.5 Amenity pivots

`property_booking_property_amenity`:

- `property_id`, `amenity_id`, nullable short `detail`, timestamps;
- unique `property_id`, `amenity_id`.

`property_booking_unit_type_amenity`:

- `unit_type_id`, `amenity_id`, nullable short `detail`, timestamps;
- unique `unit_type_id`, `amenity_id`.

The optional detail can state safe display context such as "free on-site" or
"private bathroom"; it does not hold arbitrary configuration.

### 4.6 `property_booking_unit_types`

Defines a sellable physical accommodation description within a property.

Fields:

- identity: `id`, `ulid`, `property_id`, unique-per-property `code` and `slug`,
  `name`, `status`;
- actors: nullable `created_by`, `updated_by`;
- content: nullable `short_description`, `description`;
- physical layout: nullable decimal `size_square_metres`, unsigned
  `bedroom_count`, `bathroom_count`, `living_room_count`, `bed_count`, and

- occupancy: `maximum_guests`, `maximum_adults`, `maximum_children`,
  `maximum_infants`, `allows_infants_on_top`;

- merchandising: nullable `meta_title`, `meta_description`, `published_at`;

Constraints/indexes:

- unique `property_id`, `code` and `property_id`, `slug`;
- public index on `property_id`, `status`, `published_at`;
- occupancy and featured indexes used by search;

Media collections:

Fields:

  `maximum_advance_days`;

### 4.10 `property_booking_availability_blocks`

Fields:

Indexes cover `unit_id`, `status`, `starts_at`, `ends_at` and property/calendar

Stores reusable guest identity/contact details independently of Aureon users.

- names: nullable `title`, required `first_name`, nullable `middle_name`,

- contact: nullable `email`, `phone`, `alternate_phone`;
- personal: nullable `date_of_birth`, `nationality_country_code`;

  `identity_number_ciphertext`, keyed-HMAC `identity_number_hash`,
  `identity_country_code`;
- address: nullable `address_line_1`, `address_line_2`, `city`, `region`,
  `postal_code`, `country_code`;
- safety contact: nullable `emergency_contact_name`,
  `emergency_contact_phone`;
- nullable internal `note`;
- nullable `created_by`, `updated_by`;
- `created_at`, `updated_at`, `deleted_at`.

Constraints/indexes:

- indexes on normalized email, phone, and name;
- unique nullable `identity_type`, `identity_number_hash` pair;

No identity-document media collection is included in version one. That requires

### 4.14 `property_bookings`

Owns the reservation, immutable guest/property snapshots, lifecycle, totals,

- occupancy totals: `adult_count`, `child_count`, `infant_count`;
- currency/totals: `currency`, `accommodation_subtotal_minor`,
  `charges_subtotal_minor`, `discount_minor`, nullable `discount_reason`,
  `tax_minor`, `total_minor`, `required_deposit_minor`, `paid_minor`,
  `tax_inclusive`;

  `property_address_summary`;
- primary guest snapshots: `guest_first_name`, nullable `guest_middle_name`,
  `guest_last_name`, nullable `guest_email`, `guest_phone`,

Stores one unit-type/rate-plan line and its immutable pricing snapshots. A

Placed stay snapshots are not edited directly. Modification runs a booking

### 4.16 `property_booking_unit_assignments`

Allocates a concrete unit to one booking stay and is the authoritative source
for consumed interval availability.

Fields:

- `id`, `ulid`, `property_id`, `booking_id`, `booking_stay_id`, `unit_id`;
- `status`, `starts_at`, `ends_at`;
- nullable unique unsigned-big-integer `active_stay_guard`, populated with
  `booking_stay_id` while active and cleared on release;
- nullable `assigned_by`, required `assigned_at`, nullable `released_by`, `released_at`,
  `release_reason`;
- `created_at`, `updated_at`.

Indexes:

- overlap index on `unit_id`, `status`, `starts_at`, `ends_at`;
- booking and stay lookup indexes;
- unique active-stay guard prevents two active units for one stay.

No ordinary unique constraint can prevent interval overlap. The allocation
service's deterministic unit-type/unit locks and overlap query are mandatory.

### 4.17 `property_booking_guest_assignments`

Associates occupants with a booking and optional stay.

Fields:

- `booking_id`, `guest_id`, nullable `booking_stay_id`;

### 4.18 `property_booking_charges`

### 4.19 `property_booking_payments`

Records manual or future adapter-backed tenders against a booking.

Fields:

- `id`, `ulid`, `booking_id`, nullable `reception_shift_id`, `recorded_by`;
- `method`, `status`, `currency`;
- `amount_minor`, nullable `tendered_minor`, `change_minor`,

Indexes cover booking/status, shift/status, method/reference, and payment time.
Sensitive provider or card values are rejected by a metadata sanitizer before

refunds and gateway refund orchestration remain deferred.

## 5. Migration Order

One table per migration keeps rollback and code review explicit:

1. categories;
2. properties;
3. property/user assignments;
4. amenities;
5. property amenity pivot;
6. unit types;
7. unit-type amenity pivot;
8. concrete units;
9. rate plans;
10. rate overrides;
11. availability blocks;
12. guests;
13. reception registers;
14. reception shifts;
15. bookings;
16. booking stays;
17. unit assignments;
18. guest assignments;
19. booking charges;
20. booking payments.

`down()` methods run in exact reverse dependency order and never disable
foreign-key checks to conceal an invalid sequence.

## 6. Availability And Locking Invariant

The write algorithm is database portable and service-owned:

1. validate and normalize interval/occupancy in property timezone;
2. sort requested unit-type IDs to establish deterministic lock order;
3. begin one database transaction;
4. lock the property, selected rate plans, and each unit-type row;
5. load active concrete units in ascending ID order;
6. exclude units with an active block or active assignment satisfying the
   canonical overlap predicate, expanding both the existing and requested
   departure by the property's turnover buffer so either booking receives the
   required reset time;
7. verify readiness only when the booking requires immediate check-in;
8. allocate the required number of units or throw
   `AccommodationUnavailableException`;
9. recalculate rates from locked records and server configuration;
10. write booking, stays, assignments, snapshots, totals, and activity;
11. commit, then dispatch events/notifications.

Availability previews are advisory. Placement, modification, extension, unit
move, hold resume, and check-in revalidate through the same allocator. No
controller, command, component, seeder, or listener may write an active
assignment directly.

SQLite tests verify transaction behavior and invariants. A production-engine
integration test/probe must additionally verify lock contention because SQLite
does not emulate MySQL/PostgreSQL row locking semantics.

## 7. Deletion And Retention Rules

- published/referenced property, unit type, unit, rate, guest, and register
  records are archived/soft-deleted rather than hard-deleted;
- bookings, stays, assignments, shifts, charges, and payments are never deleted
  through operator interfaces;
- cancellation, expiry, release, void, refund, and closure are explicit states;
- media deletion follows model/media policy and system activity recording;
- guest anonymization is a future privacy workflow and must preserve legally
  required financial snapshots without retaining unnecessary identity values.

## 8. Factory Contract

Every model has a module-owned factory with valid default relationships and
state methods for meaningful lifecycle cases. Factories may supply deterministic
ULIDs through unguarded factory persistence, while ordinary mass assignment
cannot set ULIDs.

Required factory states include published property/unit type, ready/blocked
unit, active/nightly/hourly rate, open shift, held/pending/confirmed/completed
booking, checked-in stay, active/released assignment, and completed payment.

The optional demo seeder uses services where business invariants matter and is
never invoked by the root production seeder unless an adopter opts in.
