# Commerce ULID Contract

**Status:** Approved module convention.

## Source and Adaptation

This contract adapts the separate-column strategy documented in:

- `.docs/model-ulid/ULID_IMPLEMENTATION_PLAN.md`
- `.docs/model-ulid/user-model-ulid-route-migration-2026-06-26.md`

The source documents were written for another application. This version is
limited to Laravel Aureon, Spatie Media Library, Livewire 4, and the Commerce
module's new tables.

## Architectural Decision

ULID is a separate route identifier, not a primary key.

```text
id    BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY
ulid  CHAR(26) UNIQUE NOT NULL
```

Consequences:

- foreign keys and polymorphic media identifiers remain integer based;
- joins and internal service signatures retain integer IDs/model instances;
- browser-facing and externally shared resource URLs do not expose sequential
  IDs;
- a unique constraint provides the lookup index, so no duplicate index is
  created;
- ULID is identification and obfuscation, not authorization.

## Required Models

| Model | Why ULID is required | Route behavior |
| --- | --- | --- |
| `ProductCategory` | Administrative resource | Admin ULID, storefront slug |
| `Product` | Administrative/API resource | Admin ULID, storefront slug |
| `Customer` | POS/admin resource containing PII | ULID |
| `Register` | POS configuration resource | ULID |
| `TillSession` | Reconciliation resource | ULID |
| `Order` | Shared/external transaction aggregate | ULID plus authorization |
| `Payment` | Payment administration resource | ULID |
| `StockMovement` | Ledger detail resource | ULID |

`Stock` is addressed through `Product`; `OrderItem` exists only inside an
`Order`. Those child/projection models keep integer identities only.

## Migration Pattern

New module tables create the ULID with the table from day one:

```php
$table->ulid('ulid')
    ->unique()
    ->comment('Immutable external route identifier generated by HasUlid');
```

No backfill is needed for new tables. A future migration adding ULID to an
existing populated table must use the nullable, chunked backfill, unique, and
non-null sequence described in the source reference.

## Model Pattern

The module provides one reusable `HasUlid` concern. It:

- generates `(string) Str::ulid()` in a trait boot method before insert;
- preserves an explicitly supplied ULID only for controlled factories/tests;
- rejects changes to an existing ULID during update;
- returns `ulid` from `getRouteKeyName()`;
- never adds `ulid` to `$fillable`.

Models remain incrementing integer-key Eloquent models. A model route generated
with `route('...', $model)` therefore emits its ULID, while relationships still
store `$model->getKey()` as an integer.

## Public Route Rules

- Administrative resources use implicit model binding and the model's ULID
  route key.
- Storefront categories and products explicitly bind by slug for readable URLs:
  `{category:slug}` and `{product:slug}`.
- Guest order confirmation uses `{order}` resolved by ULID and Laravel signed
  URL middleware.
- Order tracking may require order number plus matching email/phone, or a signed
  link. Possession of an order ULID alone is insufficient.
- Raw integer IDs must not be emitted into HTML route URLs, notification links,
  PDFs intended for customers, or public JSON.

## Validation and Security

- Route binding naturally returns 404 for malformed or unknown ULIDs.
- Controllers and Livewire actions still authorize the resolved model.
- Locked Livewire properties may carry an ULID, but the action re-fetches and
  authorizes the model before mutation.
- Activity logs may include resource ULIDs; integer IDs remain available in
  structured model subject columns.
- ULIDs are not secrets because their leading bits encode time. Sensitive guest
  access therefore uses signatures or secondary identity validation.

## Verification Contract

Tests must prove:

1. ULIDs auto-generate and match Crockford Base32 length/alphabet.
2. ULIDs are unique across a representative factory batch.
3. Explicit factory ULIDs can be used for deterministic tests.
4. Updating an existing ULID is rejected.
5. `getRouteKeyName()` returns `ulid`.
6. ULID route binding resolves the intended model.
7. Integer route values do not resolve through ULID bindings.
8. Product media still stores the integer product key.
9. Integer foreign-key relationships remain intact.
10. Guest order routes enforce signatures or customer verification in addition
    to ULID resolution.
